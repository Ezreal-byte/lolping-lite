# Windows 同机性能实测

测量时间：2026-10-17（Asia/Shanghai）。每种方案重复 3 次，表中取中位数。

后台空闲的进程树工作集由 **450.6 MiB** 降至 **44.7 MiB**，降低 **90.1%**；私有提交降低 **93.1%**。这是一台 Windows 机器上的测量，不是所有平台或负载的保证。

| 场景 | 方案 | 工作集 MiB | 私有提交 MiB | CPU（单核等效） |
|---|---|---:|---:|---:|
| 后台空闲 | 旧 WebView 插件 0.1.1 | 450.6 | 258.1 | 0.00% |
| 后台空闲 | 独立版 0.1.0 | 44.7 | 17.9 | 0.00% |
| 连续信号（5 次/秒） | 旧 WebView 插件 0.1.1 | 516.4 | 313.0 | 44.09% |
| 连续信号（5 次/秒） | 独立版 0.1.0 | 47.2 | 20.4 | 30.51% |
| 动态表情 | 旧 WebView 插件 0.1.1 | 590.9 | 385.4 | 14.59% |
| 动态表情 | 独立版 0.1.0 | 49.5 | 23.0 | 15.13% |
| 设置打开、无交互 | 旧 WebView 插件 0.1.1 | 未测 | 未测 | 未测 |
| 设置打开、无交互 | 独立版 0.1.0 | 164.9 | 112.9 | 0.00% |
| 关闭设置后空闲 | 旧 WebView 插件 0.1.1 | 未测 | 未测 | 未测 |
| 关闭设置后空闲 | 独立版 0.1.0 | 44.4 | 17.6 | 0.00% |

连续信号的 CPU 中位数从单核等效 44.09% 降至 30.51%（约降低 30.8%）；动态表情从 14.59% 升至 15.13%，因此不能把 CPU 改善推广到所有负载。设置打开的三次 CPU 样本为 0.00%、14.49%、0.00%，表中展示中位数。0.00% 表示短采样窗内未观察到可分辨的 CPU 时间增量，不代表进程绝对不消耗 CPU。

生产模式另完成 20 次设置窗口打开／关闭：主进程私有提交的前五次中位数为 15.04 MiB、后五次为 15.10 MiB，相差 68 KiB（0.44%）；第 13–20 次保持相同值，没有逐次增长。设置子进程均已退出，输入 helper 全程未重启。重复启动、三个并发启动都复用原实例，`--quit` 成功清理主进程、helper 和打开的设置窗口。完整序列见 [生命周期原始记录](windows-lifecycle-report.json)。

环境：Microsoft Windows 11 专业版 10.0.26200；Intel(R) Core(TM) Ultra 5 125H；18 逻辑处理器；32221 MiB 内存。显示器：2880×1800，150% 缩放。

统计完整应用进程树，包含输入 helper、旧 WebView2 子进程和打开时的原生设置进程；新应用启用生产托盘。旧方案排除无法单独归属的共享 DBX 宿主，因此其“设置打开／关闭”两项未测，不能据此作设置页的同比结论。

两种方案使用相同尺寸、默认 9 表情及同一份 bee_mad.webp 动画，静音；连续信号通过真实渲染器的预览命令每 200 ms 发出，动态表情每 1.8 秒重新播放。空闲等待 22 秒回收缓存，采样窗 6 秒。设置开关另由桌面验收执行 20 次。

工作集相加可能重复计算共享页，私有提交不等于驻留物理内存；GPU 内存未计入。内存为采样窗末的瞬时读数，不代表峰值上限。CPU 为进程累计 CPU 时间差折算的单核占用，和任务管理器按整机归一化的百分比不同。若采样期间有子进程退出，CPU 可能低估，原始数据记录了退出计数。

测试使用当前安装的 WebView2 runtime，未固定历史浏览器版本；未模拟实际鼠标手势或统计输入到屏幕延迟。完整匿名原始数据：[performance-windows.json](performance-windows.json)，同时作为 Release 附件；方法与复现要求见 [性能测试说明](performance.md)。

本次测量使用本机 release 构建，原始数据中的可执行文件 SHA-256 对应该测量文件；正式分发包由同一应用代码通过 CI 构建，编译器及 Windows 运行库环境可能不同，不能用该 SHA-256 校验 CI 发行包。
