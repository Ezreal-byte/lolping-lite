# Windows 同机性能实测

测量时间：2026-10-17（Asia/Shanghai）。每种方案重复 3 次，表中取中位数。

后台空闲的进程树工作集由 **448.9 MiB** 降至 **45.0 MiB**，降低 **90.0%**；私有提交降低 **92.5%**。这是一台 Windows 机器上的测量，不是所有平台或负载的保证。

连续信号的 CPU 中位数从单核等效 30.11% 变为 30.55%；动态表情从 15.12% 变为 15.24%，本次采样未显示 CPU 占用下降，不应将内存降幅解释为 CPU 改善。设置打开的 CPU 样本为 0.00%、0.00%、0.00%，表中展示中位数。0.00% 表示短采样窗内未观察到可分辨的 CPU 时间增量，不代表进程绝对不消耗 CPU。

生产模式另完成 20 次设置窗口打开／关闭：主进程私有提交的前五次中位数为 14.92 MiB、后五次为 15.00 MiB，相差 88 KiB（0.58%）；第 16–20 次保持相同值，没有逐次增长。设置子进程均已退出，输入 helper 全程未重启。重复启动、并发启动及 `--quit` 检查通过。完整序列见 [生命周期原始记录](windows-lifecycle-report.json)。

环境：Microsoft Windows 11 专业版 10.0.26200；Intel(R) Core(TM) Ultra 5 125H；18 逻辑处理器；32221 MiB 内存。显示器：2880×1800，150% 缩放。

统计完整应用进程树，包含输入 helper、旧 WebView2 子进程和打开时的原生设置进程；新应用启用生产托盘。旧方案排除无法单独归属的共享 DBX 宿主，因此其“设置打开／关闭”两项未测，不能据此作设置页的同比结论。

进程归属同时核对父子创建时间及实际取数时的进程身份，排除 Windows 复用进程编号造成的错误后代；采样失败会报错，不记为零。最终三轮旧版均为 9 个进程，原生版为 3 个、打开设置时为 4 个，采样窗口内没有子进程退出。审计中发现的一组错误归属样本已作废，本报告全部使用修正后重新完成的三轮测量。

两种方案使用相同尺寸、默认 9 表情及同一份 bee_mad.webp 动画，静音；连续信号通过真实渲染器的预览命令每 200 ms 发出，动态表情每 1.8 秒重新播放。空闲等待 22 秒回收缓存，采样窗 6 秒。设置开关另由桌面验收执行 20 次。

工作集相加可能重复计算共享页，私有提交不等于驻留物理内存；GPU 内存未计入。内存为采样窗末的瞬时读数，不代表峰值上限。CPU 为进程累计 CPU 时间差折算的单核占用，和任务管理器按整机归一化的百分比不同。若采样期间有子进程退出，CPU 可能低估，原始数据记录了退出计数。

测试使用当前安装的 WebView2 runtime，未固定历史浏览器版本；未模拟实际鼠标手势或统计输入到屏幕延迟。完整匿名原始数据：[performance-windows.json](performance-windows.json)，同时作为 Release 附件；方法与复现要求见 [性能测试说明](performance.md)。

本次 Windows 测量使用提交 [`3121f44`](https://github.com/Ezreal-byte/lolping-lite/commit/3121f44) 的本机 release 构建，随包提供 vcruntime140.dll 14.51.36247.0，原始数据中的可执行文件 SHA-256 对应该测量文件。后续 Linux 和打包调整未改变本次 Windows 测量文件。正式分发包通过 CI 构建，编译器及 Windows 运行库环境可能不同，不能用测量文件的 SHA-256 校验 CI 发行包。
